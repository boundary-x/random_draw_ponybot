# 랜덤 카드 로봇 리믹스 챌린지

카드 뽑기 → 프로젝트 설계 → 프롬프트 만들기 → 프로젝트 완성의 4단계 활동입니다.

## 프롬프트 만들기
- 브라우저에서 템플릿을 조합합니다. 생성형 AI API를 호출하지 않습니다.
- 음성 인식은 전송 문자열(forward/backward/left/right 등), KNN 핸드 포즈 분류는 학습 ID(ID1/ID2 등)를 동작에 연결합니다.
- 사용자 지정 음성 전송값은 음성 웹앱에도 동일하게 등록해야 합니다.
- 모터 방향·속도·최대 시간 또는 서보 번호·각도를 설정할 수 있습니다.
- stop, 연결 해제, 미등록 값 처리와 KNN 반복 수신/통신 중단 처리를 자동으로 지시합니다.
- 설계나 규칙을 수정하면 다시 생성하기 전에는 복사 및 다음 단계 이동이 차단됩니다.
- 이후 바이브코딩 스튜디오의 코드 생성에는 기존 AI 접속키가 필요합니다.

## 참조한 통신 계약
- [음성 v2](https://github.com/boundary-x/voice_recognition_v2/blob/main/sketch.js): 매핑된 문자열 + LF, 한 음성 세션에서 같은 값 중복 전송 억제.
- [KNN 핸드 포즈](https://github.com/boundary-x/ai_handpose_recognition/blob/main/sketch.js): ID 문자열 + LF, 반복 전송, 인식 중지/손 소실 시 stop.
- [스튜디오](https://github.com/boundary-x/vibe_coding_studio/blob/main/index.html): aiPonybot 확장 정의 및 MakeCode 규칙.

KNN의 1000ms 무수신 정지 및 이동 시간 제한은 이 생성기가 요청하는 로봇 동작 정책입니다. AI 웹앱을 수정하는 기능은 아닙니다. 서보 정지는 전원 해제가 아니라 추가 동작을 중지하고 마지막 목표각을 유지한다는 의미입니다.

## 검증
`node test.cjs`로 음성/핸드 × 이동/서보 조합, 잘못된 ID, 중복값, 수치 범위를 검사합니다.
브라우저에서 생성, 복사, 이전/다음 단계, 입력 변경 시 무효화, 모바일 390px 화면을 확인했습니다.
생성된 MakeCode 코드의 컴파일 및 실제 Bluetooth·포니봇 동작은 수업 장비로 별도 확인해야 합니다.

## 기본 상태 표시
모든 생성 프롬프트에 내장 LED 연결 성공(✓)/미연결·해제(×) 아이콘과 OLED 장치 이름·연결 상태·마지막 수신 데이터 표시를 포함합니다. 장치 이름은 control.deviceName()의 고유 이름이며, OLED는 aiPonybot.showString을 사용합니다. 수신 원문과 표시 문자열을 분리하고 같은 값 반복 수신에 따른 중복 갱신을 방지합니다.

실제 Chrome 스튜디오에서 음성/모터 코드 생성 및 Bluetooth 확장 추가 후 블록 변환을 확인했습니다. 초기 프로젝트에는 Bluetooth가 없었고 기존 radio/ws2812b/ai-ponybot-light와 충돌했습니다. 필수 확장 안내와 포니봇 소스의 회전 enum 대응을 생성기에 보완했습니다. KNN 실제 생성 테스트는 사용자 중단으로 미완료이며, 새 기본 표시 요구사항의 실제 생성·실기 검증은 아직 수행하지 않았습니다. 생성기 단위 검사 4개 조합은 통과했습니다.
